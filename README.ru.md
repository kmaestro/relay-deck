# RelayDeck

[English](README.md) | **Русский**

RelayDeck — локальное приложение для работы с HTTP API. Интерфейс открывается в нативном окне BosonPHP, запросы выполняет Symfony HttpClient, а рабочие данные сохраняются в SQLite.

HTTP-запросы выполняются в PHP и не ограничены браузерным CORS. HTML, CSS и JavaScript поставляются вместе с приложением; для интерфейса не требуется веб-сервер.

![Интерфейс RelayDeck с коллекцией запросов, параметрами URL и JSON-ответом](docs/images/relaydeck-interface.png)

*Интерфейс с демонстрационными данными.*

## Возможности

- Методы GET, POST, PUT, PATCH, DELETE, HEAD и OPTIONS; HTTP и HTTPS.
- Параметры URL, заголовки и таймаут от 1 до 120 секунд, по умолчанию 30 секунд.
- Тело запроса: JSON, текст, `application/x-www-form-urlencoded` и `multipart/form-data` с локальными файлами.
- Авторизация: No Auth, Bearer Token, Basic Auth и API Key в заголовке или query.
- Ответы: HTTP-статус, время, размер, заголовки, форматированный JSON, исходное тело и Preview для HTML, SVG, изображений и PDF.
- Коллекции, вложенные папки и сохранённые запросы; переименование запроса через меню `⋯`.
- История: в базе сохраняются последние 200 записей, в интерфейсе показываются последние 100.
- Окружения и переменные `{{name}}`, включая вложенные значения. В URL и полях Key/Value вкладки Headers доступно автодополнение.
- Несколько независимых SQLite-баз с переключением через список **Database**, без перезапуска приложения.
- Экспорт подготовленного запроса в cURL.
- Изменяемая ширина боковой панели и адаптивный интерфейс.

## Требования

Для запуска из исходников, сборки и тестирования:

- PHP **8.4.1+** для зависимостей из текущего `composer.lock`.
- Composer 2.
- PHP-расширения `ctype`, `ffi`, `filter`, `iconv`, `json`, `mbstring`, `pcre`, `pdo`, `pdo_sqlite`, `phar`. FFI должно быть доступно в CLI.
- Для зависимостей разработки, включая PHPUnit: `dom`, `libxml`, `reflection`, `tokenizer`, `xmlwriter`.
- Для HTTP(S) рекомендуются `curl` и `openssl`.

Системные зависимости нужны и при запуске готовой нативной сборки:

| ОС | Требования |
| --- | --- |
| Linux | GTK 4.12+, WebKitGTK 6.0, libadwaita |
| Windows | Windows 10+ и WebView2 Runtime |
| macOS | macOS 14+ |

Для Ubuntu/Debian:

```bash
sudo apt install libgtk-4-1 libwebkitgtk-6.0-4 libadwaita-1-0
```

Версии системных библиотек должны соответствовать требованиям Boson. См. [установку BosonPHP 0.19](https://bosonphp.com/doc/0.19/installation) и [WebView2 Runtime](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).

## Установка приложения в Linux

```bash
composer install-desktop
```

Команда собирает текущие исходники для архитектуры вашего Linux — amd64 или ARM64 — и устанавливает самостоятельную копию приложения **для текущего пользователя**. Каталог установки определяется `XDG_DATA_HOME`; по умолчанию это `~/.local/share`. Установка в `/opt` для всех пользователей текущим скриптом не реализована.

При стандартных настройках устанавливаются:

| Компонент | Путь |
| --- | --- |
| Программа | `~/.local/share/relay-deck/relay-deck` |
| Библиотека Boson | `~/.local/share/relay-deck/libboson-linux-*.so` |
| Ярлык меню приложений | `~/.local/share/applications/app.saucer.relaydeck.desktop` |
| Иконка | `~/.local/share/icons/hicolor/scalable/apps/relay-deck.svg` |

Ярлык запускает установленный executable. PHP, исходники и ресурсы встроены в него: после установки репозиторий и системный PHP для запуска не нужны. Системные библиотеки GTK, WebKitGTK и libadwaita должны оставаться установленными.

Для сборки через `composer install-desktop` необходимы зависимости разработки. При первом запуске команды компилятор скачивает инструменты сборки; они кешируются в `build/.desktop-install/.temp`. Промежуточная сборка находится в `build/.desktop-install/app`.

Чтобы установить уже собранное приложение и пропустить сборку:

```bash
php tools/install-desktop.php build/linux/amd64/relay-deck
```

Соответствующая библиотека `libboson-linux-*.so` должна лежать рядом с указанным executable. Установщик копирует оба файла в каталог установки и обновляет ярлык.

Повторная установка обновляет программу и сохраняет её `storage/` с базами и настройками. Данные из `storage/` репозитория автоматически не переносятся. Перезапустите приложение после обновления.

Иконка Linux связывается с окном через ярлык `app.saucer.relaydeck.desktop`. На Windows иконку окна задаёт встроенный PNG favicon. Ограничения favicon на Linux/GTK4 и macOS описаны в [документации событий WebView](https://bosonphp.com/doc/0.19/webview-events).

## Хранилище и базы данных

При первом запуске без сохранённых настроек приложение создаёт пустую базу `storage/app.sqlite`:

| Способ запуска | Хранилище по умолчанию |
| --- | --- |
| `php index.php` | `storage/` в корне проекта |
| После `composer install-desktop` | `$XDG_DATA_HOME/relay-deck/storage/`, по умолчанию `~/.local/share/relay-deck/storage/` |
| Нативная сборка или PHAR | `storage/` рядом с executable или PHAR |

Реестр баз и активная база сохраняются в `storage/settings.json`. Сам файл базы содержит коллекции, запросы, историю и окружения. Если сохранённый выбор базы отсутствует и рядом уже есть совместимая `storage/app.sqlite`, приложение использует её. Настройки прежних версий из системного config-каталога переносятся в соседнее хранилище после успешного открытия базы.

Если создание базы не удалось, появится экран выбора папки. Если ранее выбранная база недоступна, приложение предложит повторить подключение или выбрать другой файл.

В верхней панели через **Database** можно:

- открыть существующую базу RelayDeck с расширением `.sqlite`;
- создать новую базу: указать имя, например `work-api.sqlite`, затем выбрать папку. Расширение `.sqlite` добавляется автоматически.

Существующая база открывается по выбранному пути, без копирования. Файл и его папка должны быть доступны для записи. Поддерживаются несколько баз в одной папке и до 64 баз в реестре. Произвольная SQLite-база или файл `console.sql` не подходят: требуется совместимая схема RelayDeck.

При переключении базы редактор запроса и текущий ответ сбрасываются. Если есть несохранённые изменения, приложение запрашивает подтверждение. Ошибка открытия другой базы сохраняет прежнюю активную сессию; недоступная база остаётся в списке с пометкой `unavailable`.

Для резервной копии закройте приложение и скопируйте нужные файлы `.sqlite` и `settings.json`. Реестр содержит абсолютные пути к базам: после переноса их в другое место откройте новые пути через **Database**.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `RELAYDECK_DEBUG` | Включает WebView DevTools, например при значении `1` |
| `RELAYDECK_STORAGE_DIR` | Принудительно использует `app.sqlite` в указанной папке; управление и переключение баз отключаются |
| `RELAYDECK_CONFIG_DIR` | Задаёт папку для `settings.json`; пути самих баз выбираются отдельно |
| `XDG_DATA_HOME` | Задаёт базовый каталог пользовательской установки в Linux |

Примеры запуска из исходников:

```bash
RELAYDECK_DEBUG=1 php index.php
RELAYDECK_STORAGE_DIR=/absolute/path/to/data php index.php
RELAYDECK_CONFIG_DIR=/absolute/path/to/config php index.php
```

Используйте абсолютные пути. При `RELAYDECK_STORAGE_DIR` выбранная база не записывается в реестр. Для совместимости поддерживаются прежние имена `API_CLIENT_DEBUG` и `API_CLIENT_STORAGE_DIR`.

Если каталог приложения доступен только для чтения, задайте доступный для записи `RELAYDECK_CONFIG_DIR`: даже после выбора другой папки для базы приложению нужно сохранять реестр и настройки.

## Экспорт в cURL

Кнопка **cURL** рядом с **Save** открывает подготовленную команду; **Copy** копирует её. Экспорт подставляет переменные активного окружения, включённые параметры, заголовки, авторизацию и тело запроса. Сам экспорт не отправляет запрос и не добавляет запись в историю.

Команда предназначена для POSIX shell, например bash или zsh, и требует установленного `curl`. Для multipart, бинарных данных и больших текстовых тел используется `base64 -d` с передачей тела через stdin. Команда содержит подставленные секреты и байты выбранных файлов, поэтому перед передачей другим людям проверьте её содержимое.

## Ограничения

- Проверка TLS-сертификатов включена.
- Тело ответа ограничено **2 МиБ** (2 097 152 байта). При превышении лимита загрузка прекращается, ответ помечается как усечённый; Preview для него недоступен.
- Суммарный размер файлов во включённых полях одного multipart-запроса ограничен **25 МиБ** (26 214 400 байт).
- Содержимое выбранных файлов не сохраняется в коллекциях и истории. Перед повторной отправкой загрузите файлы заново.
- Запросы следуют не более чем 10 перенаправлениям. Таймаут применяется и к общей длительности запроса.
- Экспортированная команда cURL не имеет ограничения приложения на размер ответа.
- HTML/SVG Preview удаляет скрипты и обработчики событий, блокирует внешние ресурсы и использует sandbox. Отображение PDF зависит от возможностей системного WebView.

Bearer-токены, пароли Basic Auth, API keys и значения secret-переменных хранятся в SQLite без шифрования. Пометка secret скрывает значение в интерфейсе. Сохраняйте базы в доверенных папках и не открывайте одну базу одновременно в нескольких экземплярах приложения.

## Сборка для распространения

```bash
composer compile
```

Команда запускает Boson Compiler и собирает все цели из `boson.json`:

| Каталог | Программа | Нативная библиотека рядом с программой |
| --- | --- | --- |
| `build/linux/amd64/` | `relay-deck` | `libboson-linux-x86_64.so` |
| `build/linux/aarch64/` | `relay-deck` | `libboson-linux-aarch64.so` |
| `build/windows/amd64/` | `relay-deck.exe` | `libboson-windows-x86_64.dll` |
| `build/macos/amd64/` | `relay-deck` | `libboson-darwin-universal.dylib` |
| `build/macos/aarch64/` | `relay-deck` | `libboson-darwin-universal.dylib` |
| `build/phar/` | `relay-deck.phar` | Библиотеки для всех поддерживаемых платформ |

`arm64` в конфигурации нормализуется в имя каталога `aarch64`. Чтобы собрать только отдельные платформы, оставьте соответствующие записи в `target` файла `boson.json`.

Передавайте нативную программу вместе с указанной библиотекой из того же каталога. PHP, зависимости и ресурсы встроены в executable. PHAR запускается через системный PHP с необходимыми расширениями и нативной библиотекой соответствующей ОС:

```bash
php build/phar/relay-deck.phar
```

Данные проекта в сборку не включаются. Папка `storage/` создаётся приложением при первом запуске; отдельного post-build шага нет. Компилятор пересоздаёт целевые каталоги сборки, поэтому сохраните базы, если запускали приложение непосредственно из `build/`.

Подробнее: [конфигурация компилятора](https://bosonphp.com/doc/0.19/compiler-configuration) и [сборка BosonPHP](https://bosonphp.com/doc/0.19/compiler-building).

## Тесты

```bash
composer test
```

Набор тестов проверяет:

- подстановку переменных, HTTP-запросы, валидацию, таймауты и ограничение ответа;
- cURL: экранирование shell-аргументов, заголовки, авторизацию и точную передачу тел и файлов;
- SQLite-схему, миграции, настройки и переключение независимых баз;
- сохранение активной сессии при ошибке открытия другой базы;
- HTML-шаблоны и экранирование данных;
- установку Linux-приложения, запуск после удаления тестового репозитория, обновление с сохранением данных и ошибку отсутствующей библиотеки.

HTTP-тесты используют `MockHttpClient`. Тесты cURL проверяют команду через `/bin/sh`, заменяя сетевой вызов записью аргументов; для этих проверок нужен `base64`. Тесты установщика используют временные каталоги и подставной компилятор. Набор не обращается к интернету и не запускает настоящий GUI; проверки установщика выполняются в Linux.

## Структура проекта

```text
src/
  Application/   # окно, HTML renderer, пути хранения и управление рабочими сессиями
  Boson/         # PHP ↔ JavaScript bindings, выбор и переключение баз
  Database/      # PDO SQLite и миграции схемы
  DTO/           # запрос и ответ
  Environment/   # подстановка переменных
  Exception/     # ошибки приложения и HTTP
  Http/          # выполнение запросов и экспорт cURL
  Storage/       # коллекции, запросы, история и окружения
resources/
  index.html
  storage-setup.html
  css/app.css
  js/app.js
  js/storage-setup.js
  icons/app.svg
  icons/app.png
tools/
  build-desktop.php
  install-desktop.php
storage/         # создаваемые локальные базы и настройки
tests/
index.php
boson.json
composer.json
composer.lock
phpunit.xml
```

`index.php` подключает Composer и запускает `RelayDeckApplication`. `HtmlRenderer` встраивает CSS, JavaScript, логотип и favicon в локальные документы WebView. PHP-сервисы доступны через Boson Function Bindings; ответы имеют формат `{ok, data}` или `{ok, error}`.

Документация API: [Bindings](https://bosonphp.com/doc/0.19/bindings-api) и [WebView](https://bosonphp.com/doc/0.19/webview).
